# Read parity: default (safety-first) vs trusted_input

_2026-07-09 11:38:56 UTC · commit `075d341`_

Generated by `bench/read_parity_bench.sh`. Proves the P5 claim from the memory-safety plan:
`trusted_input=true` (skips only the untrusted-input DoS/OOM budget checks — bounds checks are
unconditional and always run, see [docs/SAFETY.md](https://github.com/yoavbendor/nanolance/blob/main/docs/SAFETY.md))
is not measurably faster
than the default, fully-checked read. Dataset: 1000000 rows, 4 columns (plain int64, low-cardinality
utf8, high-cardinality utf8, constant int64) — a mix the writer auto-encodes as
bitpack/RLE/dict-RLE/constant/plain.

## Environment
```
Linux vm 6.18.5 #1 SMP PREEMPT_DYNAMIC @0 x86_64 x86_64 x86_64 GNU/Linux
c++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
```

## Results
```
mode           |    best ms |     avg ms
---------------+------------+-----------
default        |    135.444 |    215.246
trusted_input  |    137.844 |    144.579
```

trusted/default best-ms ratio: **1.018x** (best of 9 reads each; ~1.0x means no
measurable difference — the checks trusted_input skips already validate once per page/header,
not per value, so they cost nothing to begin with).
