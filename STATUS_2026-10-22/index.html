    Status, 2026-10-22 (the overnight run)¶

    Two branches: - claude/nanolance-optimization-review-h3rxi7 (main work). Everything here passed the full suites before it was pushed, and CI is green on its head. - claude/nanolance-optimization-review-h3rxi7-highrisk: work that changes what nanolance writes in new ways. It is the main branch plus MemWAL setup and the jieba and lindera tokenizers, one commit each, so it can be merged whole or up to any commit.

    Done tonight (main branch)¶

    What Result
    cleanup_old_versions on S3 (finishes item 8) Lance's rules on the store's LastModified (nanos3reader now reports it: ObjectInfo::last_modified_ns). Equal to a local copy for four policies, and to pylance's own cleanup. Only migrate_manifest_paths_v2 stays local-only.
    S3 races and checker (W5) pylance and nanolance processes appending, and deleting while the other appends, on one S3 dataset: nothing lost or doubled. tools/s3_real_check.py runs in CI against moto (21/21).
    S3 upload speed (W5) 8 parts in flight (was 4). 512 MiB on moto: 4.6 s vs pylance's 4.3 s (was 6.7 s). bench/s3_upload_speed.py. Uploading while encoding is the next step.
    Item 9: multi-word full-text search Block-max MaxScore pruning. On 500k documents, queries with a common word: 6-9 ms, 0.2-0.5x pylance, became 0.4-2.2 ms, 1.8-6x pylance. Rows and scores bit-identical to the exhaustive search (a differential test that a deliberately wrong bound fails).
    List reads vs Rust (backlog #84) Multi-core reads of nanolance-written list<int64> / list<utf8> were 0.67x / 0.8x Rust: heap grow-and-trim around every decode window. Pooled buffers: 3.8 to 2.6 ms and 3.5 to 2.2 ms, level with Rust's own files.
    CI fixes Python 3.9 wheels (nanobind pin per Python version); DuckDB 2.0 pushes IN filters as if_else(is_valid(s), ...), now understood; a pylance race in an HNSW test.
    Build hygiene Python build tools pinned; CMake refuses GCC < 12 (nanom needs it) with a clear message; lance-c tests no longer abort on NFS.
    Flaky tests test_vector_model_kept_or_retrained fixed (seeded, premise asserted). test_optimize_after_append did not recur in 60 runs.
    T4 (dictionary columns) Was already done; checked and marked.
    Auto cleanup on S3 Lance's lance.auto_cleanup.* hook now runs on object stores as pylance's does (five commits, interval 2: versions 3-5 left, as pylance).
    io stats on S3 io_stats_incremental() counted no writes on s3://; the sink now counts each upload.
    Full suite 4000 passed, 21 skipped, 1 xfailed (bindings, against moto); ctest all pass.

    High-risk branch¶

    • MemWAL setup (item 12, phase M1): done. initialize_mem_wal in every form, the __lance_mem_wal index entry pylance writes, mem_wal_index_details, and evaluate_sharding_spec with Lance's bucket hash. 13 more pylance tests pass (1255 expected). The entry survives every operation as pylance keeps it. Haiku wrote most of it before hitting its usage limit; I finished and reviewed it.
    • jieba tokenizer (item 11, phase J): done (docs/tasks/TOKENIZERS_J.md). jieba-rs 0.10 ported (search mode, HMM embedded). Same results and scores as pylance on random corpora; +4 pylance tests. I stopped the Haiku attempt and did it myself, as you asked. Note: pylance 12 itself aborts (a 96 GiB allocation) on some jieba queries; nanolance does not.
    • lindera tokenizer (item 11, phase L): done (docs/tasks/TOKENIZERS_L.md). Lindera 3.0.7 ported: YAML config, Lindera 3 dictionary files, CSV and .bin user dictionaries, normal and decompose modes, mapping filter. Tests generate random dictionaries that both engines read; results and scores equal. +7 pylance tests (1267 expected). Token filters and the other character filters are refused by name.

    Decided, not done¶

    • ICU tokenizer: system ICU4C gives pylance's tokens on 28 of 29 probe sentences across 15 scripts. The one difference is a Japanese dictionary split: pylance gives はい|い where ICU4C gives は|いい. Close, but not equal, so it is deferred, or would be an opt-in with that caveat.
    • T6 (overlay refinements): low value. Indexes already stay in use for overlays that touch other fields, so "updating labels on an indexed embedding table" is fast today.
    • MemWAL M2 (shard writers, memtables, SSTables, LSM scanners; 7 tests): a subsystem. Needs a design first.
