    Task: the jieba tokenizer for INVERTED indexes (ROADMAP item 11, phase J)¶

    Status: done (2026-10-22, Opus; a delegated start was stopped and replaced). High-risk branch claude/nanolance-optimization-review-h3rxi7-highrisk. Item 11 is icu / jieba / lindera; this phase is jieba only. ICU (phase I) and Lindera (phase L) are not part of it: keep refusing them by name.

    Budget about 200k tokens; aim for 120k. Never read a large file whole: grep -n, then sed -n 'A,Bp' windows of at most ~120 lines. Big ones: bindings/python/nanolance/lance/dataset.py (5k+), src/index/fts/fts_index_build.cpp, src/index/fts/fts_search.cpp, jieba-rs src/lib.rs (68 KB). Cut output: | tail -15 for pytest (add -o addopts=).

    4. Implementation¶

    • C++ (src/index/fts/fts_tokenizer.cpp and a new src/index/fts/fts_jieba.cpp): the dictionary (a trie or hash of prefixes: jieba-rs uses a double-array trie; any structure giving the same DAG is fine), the DAG, the route, the HMM Viterbi, search mode, the block regexes written as character-class code (no <regex>). Every float operation in the order jieba-rs does it (f64).
    • The built-in HMM model: embedded zstd-compressed (nanolance already links zstd), parsed on first use, behind a CMake option NANOLANCE_WITH_JIEBA (default ON; the wasm build sets it OFF: there a jieba index is refused by name). Report the size the embedded model adds to the Python extension.
    • Models: base_tokenizer="jieba/<name>" loads <LANCE_LANGUAGE_MODEL_HOME>/jieba/<name>/ (config.json or dict.txt) when an index is built and when it is searched (as Lance does: measure 3.3); errors as pylance raises them (the targets: OSError for a missing user or main dictionary).
    • Both directions: nanolance searches a jieba index pylance built, pylance searches one nanolance built, results and scores equal.

    5. Tests you write¶

    bindings/python/tests/test_fts_jieba.py (require_pylance()): 3.1 and 3.2 through both engines (token lists equal document by document; queries' rows and scores equal to 1e-6), each engine searching the other's index, user dictionaries, the error cases. Point LANCE_LANGUAGE_MODEL_HOME at a temporary directory you build in the test (copy the 5 MB dictionary in only if the test can find the crate copy; otherwise use a dictionary the test writes: no test may download).

    6. Rules¶

    AGENTS.md sections 5 and 7. No skipped or weakened tests; no except Exception around failures. The local native build has -DNANOLANCE_WERROR=ON: delete helpers you stop using. Check the wasm build still configures and builds with jieba OFF (source /home/user/emsdk/emsdk_env.sh if present; else say so in the report). Do not add fields to Python classes that mirror pylance's. Do not commit, push, change branches, or run --update. Every other tokenizer's output must stay byte-identical (the existing FTS tests must pass unchanged). Builds: cd build && ninja, then cd bindings/python && python3 -m pip install -q -e . (always python3 -m pip). Run each full suite once, at the end; the bindings suite with | grep -E "^(FAILED|ERROR)|passed|failed" | tail -15.

    7. Stop and ask (question first in the report)¶

    • a token list differs from pylance's and the jieba-rs source does not explain it;
    • the embedded model would add more than 1 MB to the Python extension;
    • a pylance test that passes today fails.
