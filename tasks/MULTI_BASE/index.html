    1. Goal¶

    A Lance dataset can keep data files outside its own directory, in other "base paths" listed in the manifest. pylance 12 creates them (write_dataset(initial_bases=[DatasetBasePath(...)], target_bases=[...] | target_all_bases=True)), adds bases (ds.add_bases), and writes fragments into them (write_fragments(target_bases=), merge_insert(...).execute(..., target_bases=)). Today nanolance cannot even read such a dataset (it looks for every data file under <dataset>/data and fails with "data file is too small or unreadable"). Make nanolance read and write them as pylance does, verified against pylance on the same calls.

    2. Format facts (measured on pylance 12.0.0 in this container -- do not re-derive)¶

    Protos: .deps/rust-suite/lance-12.0.0/protos/table.proto.

    • Manifest.base_paths = 18: repeated BasePath, where message BasePath { uint32 id = 1; optional string name = 2; bool is_dataset_root = 3; string path = 4; }. Ids count from 1 in the order the bases are given (0 / absent means "the dataset itself").
    • DataFile.base_id = 7 (optional uint32); DeletionFile.base_id = 7; IndexMetadata.base_id = 9. Absent = the dataset's own directory.
    • Where a file is: base absent -> <dataset>/data/<path>. Base with is_dataset_root = false -> <base.path>/<path> (directly in the base directory). Base with is_dataset_root = true -> <base.path>/data/<path>. Deletion files: same rule with _deletions instead of data (pylance itself writes deletions of base fragments to the primary _deletions, base_id unset -- but honour a base_id if one is present). Blob sidecars sit next to their data file, so they follow it.
    • Measured example: write_dataset(t, primary, initial_bases=[DatasetBasePath(p1, name="path1"), DatasetBasePath(p2, name="path2", is_dataset_root=True)], target_all_bases=True, max_rows_per_file=100) on 300 rows -> 3 fragments with base_id None, 1, 2 (rotation: the primary first, then each base in order); files at primary/data/x.lance, p1/y.lance, p2/data/z.lance.
    • DatasetBasePath(path, name=None, is_dataset_root=False, id=None), attributes id, is_dataset_root, name, path, repr DatasetBasePath(id=0, name=Some("n"), path=/x, is_dataset_root=false) (name=None when unnamed). Exported as lance.DatasetBasePath.
    • DataFile.base_id is already decoded/encoded by the Python transaction codec (bindings/python/nanolance/lance/_transactions.py, _data_file / _encode_data_file).
    • C++: the generated codec (generated/lance_minimal.pb.hpp) keeps fields it does not know in unknown bytes (Manifest::unknown, DataFile::unknown, DeletionFile::unknown). That is how base_paths / base_id survive today. Follow the pattern of include/nanolance/row_ids.hpp (read_fragment_row_meta / write_fragment_row_meta read and replace fields 5..10 inside DataFragment::unknown) for reading Manifest.unknown field 18 and DataFile.unknown field 7. Do not regenerate the codec.

    When in doubt about behaviour, run the same call on real pylance (import lance) and copy it.
