    3. Where things are in nanolance¶

    • INVERTED build / search: src/index/fts/fts_index_build.cpp, src/index/fts/fts_search.cpp; the nested refusal: grep -rn "nested column is not supported" src bindings/python/nanolance.
    • FTS on list columns (ROADMAP Wave 1 item 1, docs/tasks/FTS_LISTS.md) changed how a document's text is collected from a column: the nested case is another source of text, not a new index format.
    • Nested path resolution for scalar indexes: grep -n "resolve.*path\|case-insensitive" src/*.cpp.
    • Transactions: read_transaction in dataset.py ~2011; manifest reading in src/dataset/dataset.cpp; V1 / V2 manifest names in src/table/manifest_writer.cpp (nanolance already reads both).

    4. Phases¶

    • N: build, search (by path, default columns, MatchQuery / phrase / boolean queries as for top-level columns), maintain (optimize_indices, compaction re-cover) INVERTED indexes on struct leaves at any depth; each engine uses the other's nested index with equal results; lance-c FTS on a nested column where lance-c takes a column name. The two N targets pass.
    • S: field 21 read (both places), manifest_needs_migration and migrate_manifest_paths_v2, and the decisions above recorded in ROADMAP T5. The S target passes.
