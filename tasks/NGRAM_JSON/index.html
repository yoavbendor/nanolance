    1. Facts (measured on pylance 12.0.0 here)¶

    NGRAM (create_scalar_index(col, index_type="NGRAM"), string / large_string columns): - One file ngram_postings.lance: schema tokens: uint32 (nullable) + posting_list: binary not null with field metadata lance-encoding:compression = none; one row per distinct token, sorted by token. posting_list = a RoaringTreemap serialization of the row ids (u64 LE count of 32-bit high keys, then per key [u32 LE high][portable 32-bit Roaring]) -- not the RowAddrTreeMap format of serialize_treemap. Token 0 holds the null rows. Example: 5 rows ["apple pie","Banana!",None,"","ÉCOLE ab"] -> 11 rows, token 0 -> {2}. - Tokenizing (ngram.rs 87-160): per value, RawTokenizer + LowerCaser + AsciiFoldingFilter (one token = the whole value lowered and folded), then NgramTokenizer::all_ngrams(3, 3) over characters, then AlphaNumOnlyFilter (keep a trigram only if every char is_ascii_alphanumeric). Token id: ngram_to_token (base 37; '0'-'9' -> 1-10, 'a'-'z' -> 11-36; first char * 37^2 ...). nanolance already has lower-case and ASCII-folding code in src/index/fts/fts_tokenizer.cpp: reuse it. - Manifest: type_url /lance.table.NGramIndexDetails (empty message), index_version 0, describe_indices()[i].index_type == "NGram"; stats.index_stats(name): index_type "NGram", indices / segments = [{"num_ngrams": N}]. - Search (ngram.rs 506-600): contains(col, 'x') (and Lance's other forms it routes to TextQuery::StringContains -- grep StringContains in lance-index's scalar/expression.rs; check LIKE '%x%') -> a needle of < 3 chars: index knows nothing (recheck all rows); any needle trigram missing from the index: exact empty; no trigrams after filtering: recheck all; else the intersection of the posting lists as candidates to recheck (at_most). regexp_like uses ngram/ngram_regex.rs -- out of scope (treat as recheck all) unless a target test needs it. Results always equal a scan without the index; the plan shows ScalarIndexQuery: query=[contains(w, Utf8("apple"))]@w_idx(NGram) (nanolance builds this line in src/dataset/index_search.cpp ~1012). - Maintenance like the other scalar kinds: optimize_indices deltas, compaction re-cover, create_index_uncommitted(index_type="NGRAM", fragment_ids=...), merge_existing_index_segments, commit_existing_index_segments, drop, empty dataset.

    JSON (create_scalar_index(col, IndexConfig(index_type="json", parameters={"target_index_type": "btree", "path": "x"})), on a JSON column): - Files = a normal BTree (page_data.lance: values: <T>, ids: uint64 not null; page_lookup.lance: min, max, null_count, page_idx, metadata batch_size, range_partitioned = false) over the value extracted at path. nanolance already writes BTree files: reuse the builder with the extracted column. - Value type <T> (json.rs 531-590): the type of the first non-null extracted value -- bool -> Boolean, int -> Int64, float -> Float64, string -> Utf8, array / object -> LargeBinary; all null -> Utf8. Later rows must be compatible (Float64 accepts ints) or the build fails with JSON path '{path}' expected {T:?}, but batch row {i} has JSON type {J:?}. Missing path = null. - Manifest: type_url /lance.index.pb.JsonIndexDetails = {string path = 1; Any target_details = 2} with target_details the BTree's details Any; index_version 0; describe index_type "Json", details {"path": "x", "target_details": {}}; stats.index_stats: index_type "BTree", indices [{"min":..,"max":..,"num_pages":..}] as for a BTree. Default name <col>_idx. - Queries routed (json.rs ~300-460): json_get_int / json_get_float / json_get_bool / json_get_string(col, '<path>') <op> literal where the function's type equals the index's <T> and the path string equals the index path; plan line ScalarIndexQuery: query=[Json(j = 11->x)]@j_idx(BTree). json_extract is never routed. nanolance evaluates these functions already (src/expr/expr.cpp ~1650).

    ngram tokenizer for INVERTED (N3): base_tokenizer="ngram", min_ngram_length (default 3), max_ngram_length (default 3), prefix_only; stem / remove_stop_words default false for it. Port ngram_tokenizer.rs (221 lines, read whole) into src/index/fts/fts_tokenizer.cpp's chain. Oracle test_fts_ngram_tokenizer (read it).
