    Task: deferred index remap and the Fragment Reuse Index; the Compaction plan / execute / commit API¶

    Status: delegated (implementer: Claude Haiku 5.5, reviewer: Claude Opus 5.5). ROADMAP "Index plan for AI users", Wave 1, item 4. Two sessions: R1 (read pylance's FRI), R2 (write it, and the Compaction API). Do only the phase you are given.

    0. Context budget (read this first)¶

    Budget about 200k tokens; aim for 120k. Never read a large file whole: grep -n, then sed -n 'A,Bp' windows of at most ~120 lines. Big ones: src/index/index_search.cpp, src/dataset/dataset_ops.cpp, src/dataset/index_optimize.cpp, src/index/vector/vector_search.cpp, src/index/fts/fts_search.cpp, bindings/python/nanolance/lance/dataset.py (3.5k+). Lance's Rust: read only the files named here. Cut output: | tail -15 for pytest (add -o addopts=), | tail -5 for tools/pylance_suite.py.

    1. Goal¶

    compact_files(defer_index_remap=True) (and Compaction.commit(..., options={"defer_index_remap": True})) compacts without rewriting the indexes: it adds a system index __lance_frag_reuse that maps the old row addresses to the new ones, and the indexes keep their old row addresses while their fragment coverage moves to the new fragments. Searches translate through it. nanolance today, on such a dataset, ignores every scalar index (index_candidates in src/index/index_search.cpp about line 1307 returns early: correct, but a full scan), hides the system index from list_indices / describe_indices, and cannot write one. Targets in .deps/pylance-tests/v12.0.0/tests/test_optimize.py (lines 500-590): test_defer_index_remap, test_defer_index_remap_via_commit_options[True|False], test_describe_indices_matches_list_indices_for_frag_reuse; and the Compaction.plan tests the suite lists as failing (grep -n "Compaction.plan" .deps/pylance-tests/v12.0.0/tests/*.py).

    4. Phases¶

    • R1 (read): decode the FRI (inline and external); every index kind (scalar, vector, full-text) searched through it on pylance-made datasets, with the same rows as pylance; the early return goes; list_indices / describe_indices / stats show the system index as pylance does; optimize_indices and later compactions keep or drop it as pylance does (measure each with pylance in your test, both engines on the same dataset). test_describe_indices_matches_list_indices_for_frag_reuse passes on pylance-written data.
    • R2 (write): CompactionOptions.defer_index_remap (C++), compact_files(defer_index_remap=True), and Compaction.plan / CompactionTask.execute / Compaction.commit(options=...) in Python; the FRI nanolance writes is read by pylance with the same results. All target tests pass.

    R1 outcome (2026-10-20): done for scalar indexes in one Haiku session; reviewed. The FRI is decoded (inline and external details.binpb, the per-version remap from changed_row_addrs and the digests; cached per dataset and uuid); BTREE, BITMAP, ZONEMAP and BLOOMFILTER answers are remapped (deleted rows drop, moved rows land in their new fragments; not with stable row ids, whose ids do not move), coverage is remapped by Lance's straddle rule, list_indices / describe_indices show __lance_frag_reuse as pylance does, and optimize_indices no longer rebuilds an index the FRI still covers. tests/test_frag_reuse.py (9). Reviewer's decisions on the session's questions: - Vector and full-text indexes after a deferred remap are answered by an exact scan of the rewritten fragments (right rows, index not used). Translating their candidate addresses is its own phase, R1b (vector: the candidate ids in the IVF / HNSW loops and the count fill; FTS: postings and document lengths keyed by row address). - pylance 12.0.0 answers wrongly after an eager compaction on top of a deferred one (an indexed i = 600 returns no row where a scan returns one; its BTREE keeps stale addresses). nanolance does not copy wrong answers: on its own eager compaction it keeps the results right (its index metadata then differs from pylance's); on a dataset pylance left in that state it reads what is on disk, as pylance does. Recorded for an upstream report. - Index listing order (pylance sorts by name; nanolance keeps manifest order): a small item, not FRI's. The pylance targets (test_defer_index_remap*, test_describe_indices_matches_list_indices_for_frag_reuse) need nanolance's compact_files(defer_index_remap=True): R2.

Five more of pylance's tests pass (expected list 1219).
