    1. Goal¶

    pylance 12 datasets can carry branches: named lines of versions forked from a version of another branch (or main). nanolance refuses them by name today (dataset.py: raise unsupported("branches") near lines 636 and 2460, and the attribute list near line 2260; _namespace_dir.py near lines 1186 and 1765). After this task nanolance reads, creates, writes, lists and deletes branches exactly as pylance does, on disk and through the API, and shallow_clone / deep_clone work. Each engine opens and appends to the other's branches.

    Targets (.deps/pylance-tests/v12.0.0/tests/): test_dataset.py::test_branches, ::test_shallow_clone, ::test_deep_clone; test_namespace_dir.py::...::test_branch_crud_round_trip, ::test_create_branch_from_other_branch (B3). test_s3_ddb_branches and test_namespace_managed_branches need DynamoDB / S3 writes: out of scope.

    2. Facts (measured on pylance 12.0.0 -- do not re-derive)¶

    Re-run in /tmp/claude-0/-home-user/8df192dc-e0a5-50ec-ba29-4d1c2c18b24f/scratchpad/br/ (ds.lance: v1 3 rows, v2 +1 row; branch exp from v1, then one append on exp).

    Layout. A branch B lives under <root>/tree/B/ with its own _versions/, _transactions/, data/ (and _versions/latest_version_hint.json, {"version":N}, which pylance writes on every commit, main included). Branch names can contain / (Lance's branch_location.rs). Its reference is <root>/_refs/branches/B.json:

    {"parentBranch": null, "identifier": {"version_mapping": [[1, "1935c23a6df942abaf8023c96579f240"]]},
 "parentVersion": 1, "createAt": 1792482184, "manifestSize": 369, "metadata": {}}

    parentBranch is null for main, else the parent's name. identifier.version_mapping is the chain of (parent_version, 32-hex random id) from the root: a branch of a branch has two entries (its parent's, then its own). createAt is Unix seconds; manifestSize the size in bytes of the parent manifest it was forked from.

    The branch's first manifest has the same version number as the parent version it forks (branch from v1: the branch's _versions/ holds version 1), and is the parent's manifest with: - every inherited data file (and deletion file) gets base_id = 0 (DataFile field 7): base path id 0, not "the dataset itself" -- only an absent base_id means the dataset's own directory (Lance dataset.rs data_file_dir_for_base); - base_paths (Manifest field 18) gains {id: 0, is_dataset_root: true, path: <parent's root, as the dataset was opened: relative if opened relative>} (BasePath fields 1, 3, 4); - reader and writer feature flags (Manifest fields 9, 10) gain 16 (base paths); - branch (Manifest field 20) = "B"; - a new transaction file (a Clone operation; nanolance's transaction writer must learn it) in tree/B/_transactions/.

    Files written on the branch afterwards have no base_id (they live under tree/B/data/); the next version is parent version + 1 (append on exp from v1 -> exp v2 while main has its own v2). Main is never touched by a branch write.

    API (pylance 12): - ds.create_branch(name, reference=None) -> the branch as a LanceDataset at its first version. reference: None (this dataset's current version on its branch), an int version, a tag name, or a (branch, version) tuple where branch None or "main" is main and version None is that branch's latest. branch.uri is <root>/tree/<name> (absolute if the root was). A second branch of the same name fails (pylance's own message is an internal error; raise OSError containing "already exists"). - lance.dataset(<root>/tree/B) opens the branch; write_dataset(..., <root>/tree/B or the branch dataset, mode="append"/"overwrite") commits on it. - ds.checkout_version(x): x an int, a tag, or (branch, version). A missing branch: ValueError ("Not found: .../tree/nope/_versions"); a missing tag name: OSError containing "does not exist" (test_branches relies on it). checkout_latest() moves to the branch's latest. - ds.branches: list() -> {name: {"parent_branch", "branch_identifier": [(int, str), ...], "parent_version", "create_at", "manifest_size", "metadata"}}; list_ordered() (by create_at, then name: check against pylance); delete(name); replace_metadata(name, dict). Deleting "main": OSError "Ref is invalid: Branch name cannot be 'main'". Deleting a branch another branch forks from: OSError 'Ref conflict error: Branch b1 is referenced by [("b1child", 1)] versions, can not delete'. Delete removes the JSON and tree/B/. - Tags gain a branch: _refs/tags/T.json has "branch": "exp" or null; tags.create(name, ref) takes the same reference forms ((None, None) and ("main", None) are main's latest); tags.list()[t]["branch"]. - shallow_clone(target, reference): target/_versions/ gets one manifest (same version number as the source version) whose files all point at the source through base_paths (as a branch's do), plus a transaction; no data/. deep_clone(target, reference): the same, with the data (and deletion) files copied into target/ and no base path to the source. Both return the clone, opened.

    Lance's code (sources under /root/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/): lance-12.0.0/src/dataset/refs.rs (branch and tag JSON, checks, errors), .../dataset/branch_location.rs (paths), lance-12.0.0/src/dataset.rs lines 601 (create_branch), 3264 (shallow_clone), 3314 (deep_clone); the Clone transaction in lance-12.0.0/src/dataset/transaction.rs (grep -n "Clone" ...); lance-table-12.0.0/protos/table.proto (Manifest field 20 branch, 18 base_paths) and transaction.proto (the Clone operation).
