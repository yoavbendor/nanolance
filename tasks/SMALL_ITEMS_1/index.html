    1. Row-address masks: row_addr_allowlist / row_addr_blocklist, lance.dataset.serialize_row_addrs¶

    Oracle: all of .deps/pylance-tests/v12.0.0/tests/test_row_addr_prefilter.py (12 tests).

    Facts (measured): - serialize_row_addrs([0, 2, 4, ...]) returns Lance's RowAddrTreeMap serialization: u32 count of fragments, then per fragment ascending [u32 fragment id][u32 byte size][portable Roaring bitmap of the row offsets]. nanolance already writes exactly this (serialize_treemap in src/index/scalar/scalar_index.cpp) and reads it (read_treemap in src/dataset/index_search.cpp). For [1, 2, (1<<32)|5] pylance returns 58 bytes starting 02 00 00 00 00 00 00 00 14 00 00 00 3a 30 ... -- your Python output must be byte-identical (compare with pylance in your test). The Python roaring encoder exists: _serialize_roaring in bindings/python/nanolance/lance/bitmap.py. - scanner(row_addr_allowlist=bytes, row_addr_blocklist=bytes) and ScannerBuilder setters (see test_builder_setter_matches_the_kwarg): the scan keeps only rows whose address is in the allowlist and not in the blocklist, before filters, limits and ranking -- a KNN or full-text search computes its top-k over the surviving rows (test_knn_topk_is_computed_over_masked_rows). Malformed bytes: an error matching (?i)row address mask|invalid. - Implementation hint: masks are row sets per fragment, like the scalar-index candidates the scan already takes (PlannedFile::candidates in src/scan/lance_table_reader.cpp; how index_candidates feeds them in). Vector search has a RowMask (src/index/vector/vector_search.cpp), full-text search a RowMask in src/index/fts/fts_search.cpp: intersect the caller's mask there. Pass the mask from Python as bytes to the native call; decode it once in C++. - The two test_overlay_stale_replay_* tests need data overlays, which now work (src/table/overlays.cpp): they must pass once the mask is applied on every row source.

    2. lance.dataset.VectorIndexReader¶

    Oracle: tests/test_vector_index.py::test_nested_field_vector_index (and any other test using VectorIndexReader; grep). Facts: VectorIndexReader(dataset, index_name), num_partitions(), read_partition(partition_id, with_vector=False) -> a pyarrow Table with _rowid (uint64) only, plus with with_vector=True the storage column: flat (FixedSizeList[dim]) for IVF_FLAT, __pq_code (FixedSizeList[m]) for IVF_PQ -- copy the exact schema and row order real pylance returns on the same index, for IVF_FLAT, IVF_PQ and IVF_HNSW_SQ (__sq_code). The partition data is in the index's auxiliary.idx (offsets/lengths per partition are in the IVF model nanolance already decodes: load_ivf / IvfIndex in src/index/vector/vector_search.cpp). With stable row ids _rowid is the id.

    3. _take_rows of a deleted row's address¶

    ds._take_rows([address_of_a_deleted_row, ...]) returns the deleted row in nanolance; pylance leaves it out (datasets without stable row ids). Reproduce: write_dataset 300 rows, delete("id % 4 = 1"), _take_rows([(0 << 32) | 5]) -> pylance []. Fix where _take_rows resolves addresses (grep -n "def _take_rows" bindings/python/nanolance/lance/dataset.py, and resolve_row_ids in src/table/row_ids.cpp, which skips deleted rows only for stable ids). Add the case to bindings/python/tests/test_take.py against pylance.
